### Перемещение в пределах тома

Для дерева из 100 000 пустых файлов `move-new` занял 0,015166 с, а Windows Shell API — 0,130008 с. Это по одному запуску на том же дереве с обратным переименованием между ними. Проверено наличие всего дерева в назначении. Показатель «файлов/с» в TSV для этого сценария выражает размер дерева относительно задержки.

### Поиск

На 1 000 000 файлов запрос по уникальному имени в прогретом `index-dir` занял 0,016516 с по медиане трёх повторов. Построение индекса заняло отдельно 0,131217 с. Одноразовый `find` по тому же имени занял 0,107621 с с запуском процесса. Режим `index-dir` выполняет файловые проверки для кандидатов, поэтому число совпадений влияет на выигрыш.

На отдельном наборе из 100 000 файлов в режиме индексирования папки Everything 1.5.0.1424b вернула одно совпадение. Медиана из трёх запусков `es.exe -get-result-count` составила 0,033770 с, включая запуск клиента и IPC. Фоновый процесс Everything занимал 33,6 МиБ рабочего набора после построения индекса. `index-dir` нашёл то же совпадение за 0,001645 с по медиане внутри запущенного процесса, а его начальная сборка заняла 0,014203 с. Разные границы замера исключают прямое сравнение этих двух чисел как задержек поискового алгоритма. [Индексация папок Everything](https://www.voidtools.com/en-us/support/everything/folder_indexing/) · [Everything CLI](https://www.voidtools.com/support/everything/command_line_interface/)

### Границы прогона

Сравнение с Windows выполнено через `IFileOperation` из отдельного процесса. GUI Проводника оставался вне этого прогона. Проверка полного томового индекса MFT/USN требует доступа к тому, а на D: журнал оказался выключен. Каталог драйвера сгенерирован, запуск в VM требует прав и подписи. WPR отказал в доступе под текущим процессом, поэтому объём физического дискового ввода-вывода и холодный кэш остаются без результатов. [Профили Windows Performance Recorder](https://learn.microsoft.com/windows-hardware/test/wpt/built-in-recording-profiles)

В [TSV](benchmark-results.tsv) приведены счётчики процессов. `other_ops` и `other_bytes` включают запросы метаданных и управляющие операции, а `read_bytes` и `write_bytes` отображают счётчики Win32 процесса и могут включать недисковые операции. Для физических дисковых операций используй ETW. В `cpu_pct_one_core` 100% соответствует одному полностью занятому ядру. Для коротких запусков CPU-время может округляться до нуля.

## Повторение

В примерах `stdioctl.exe` берётся из каталога сборки, а `D:\Lab` — отдельная существующая папка тестового тома. `prepare` создаёт свежий каталог с GUID и печатает его путь. Используй этот путь как `%FIXTURE%`. Поддерживаются наборы 1 000, 10 000, 100 000 и 1 000 000 файлов. `flat` создаёт пустые файлы в одном каталоге, `deep` создаёт до 96 вложенных уровней, `mixed` создаёт до 64 подкаталогов с файлами от 0 байт до 1 МиБ. Данные и имена детерминированы.

```bat
stdioctl prepare D:\Lab 100000 flat
stdioctl size "%FIXTURE%"
stdioctl measure stdio-size 100000 warm zero "%CD%\stdioctl.exe" size "%FIXTURE%"
stdioctl measure win32-size 100000 warm zero "%CD%\stdioctl.exe" win32-size "%FIXTURE%"
stdioctl measure stdio-find 100000 warm zero "%CD%\stdioctl.exe" find "%FIXTURE%" file-0000042
stdioctl measure win32-find 100000 warm zero "%CD%\stdioctl.exe" win32-find "%FIXTURE%" file-0000042
stdioctl measure stdio-delete 100000 as-created zero "%CD%\stdioctl.exe" delete "%FIXTURE%" --yes auto
```

Для каждого удаления создай новое дерево и проверяй, что оно исчезло. Для сравнения потоков повтори команду с `1`, `2`, `4`, `8` и `auto`. Для Windows Shell используй новое дерево и `shell-delete --yes "%FIXTURE%"`. Для замера GUI выбери тестовую папку в Проводнике и используй Shift+Delete. Измеряй от подтверждения до исчезновения папки, а показатели процесса и диска собирай трассировкой. Удаление в корзину сравнивай отдельным сценарием.

```bat
stdioctl prepare D:\Lab 10000 mixed
stdioctl measure stdio-copy-new 10000 warm zero "%CD%\stdioctl.exe" copy-new "%NEW_DEST%" "%FIXTURE%" auto
stdioctl measure robocopy 10000 warm robocopy "%SystemRoot%\System32\robocopy.exe" "%FIXTURE%" "%ROBO_DEST%" /E /MT:8 /R:0 /W:0 /NFL /NDL /NJH /NJS /NP
stdioctl measure fastcopy 10000 warm zero "D:\Tools\FastCopy.exe" /cmd=force_copy /no_ui /log=FALSE "%FIXTURE%" "/to=%FAST_DEST%"
```

Для `copy` через Windows Shell задай существующую родительскую папку, а сверяй размер созданной внутри копии. Для `copy-new`, Robocopy и FastCopy задай отдельные новые назначения. Проверь число файлов, размер и выбранные хеши. Для перемещения отдельно измерь переименование в пределах тома и перенос на другой том. Колонка `files` обозначает размер рабочего набора. При переименовании целого дерева считается одна операция Windows, независимо от числа файлов.

Для поиска запусти `index-dir "%FIXTURE%"`, повтори `count name file-0000042` и запиши время построения отдельно. Сравнивай с `find` и `win32-find` на том же дереве. Для Everything выдели тот же каталог в Folder Indexing, дождись построения и используй `es.exe -get-result-count -path "%FIXTURE%" file-0000042`. Для томового сравнения запусти `stdioctl index X:` на томе VM с активным USN Journal, и включи соответствующий NTFS-индекс в Everything.

Счётчик прочих операций процесса снизился с 460 138 до 460 083. На смешанном наборе из 20 000 файлов медианы составили 1,804 и 1,798 с. Для каждой сборки и каждого набора было три запуска с чередованием версий и сверкой числа файлов, каталогов и логических байтов.

На одном NTFS-томе NVMe копировали реальные данные двух размеров, по три запуска на режим с чередованием. Оба режима использовали новое имя назначения. После каждой копии проверяли длину и SHA‑256. Дополнительно через `copy-new --unbuffered-large` скопировали каждое дерево и сверили SHA‑256.

### Кэш и трассировка

- `as-created` означает запуск после генерации без процедуры очистки или прогрева. `warm` для операций с каталогами означает предварительное чтение метаданных, для поиска по индексу — повторный запрос в том же процессе.
- Для `cold` подготовь наборы на тестовом VHDX, выключи VM без сохранения памяти и начни первый замер после загрузки, без предварительного обхода. Укажи, что измеряешь холодный кэш гостевой Windows и отдельно контролируешь кэш хоста и накопителя. Сам аргумент `cold` в `measure` является меткой.
- Для устойчивого сравнения чередуй инструменты, проверяй результат каждой операции, записывай версии и конфигурацию накопителей. Делай минимум три повтора, а первый расходуемый набор для каждого прогона готовь заранее.

Из командной строки администратора в VM:

```bat
wpr -start CPU -start DiskIO -start FileIO -filemode
rem Выполни один измеряемый сценарий.
wpr -stop D:\Lab\stdio-one-run.etl
```

В Windows Performance Analyzer используй графики Disk Usage и File I/O и фильтруй по диску, пути, процессу и интервалу сценария. Для Everything отдельно учитывай серверный процесс и клиент `es.exe`. [Запись трассировки Windows](https://learn.microsoft.com/en-us/windows-hardware/test/wpt/recording-for-resource-based-analysis)
